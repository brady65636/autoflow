# 20 PDF / 1,125 页批处理测试计划

## 目标与测试金字塔

验证汽车资料管线从 PDF 输入、页级抽取、section/chunk、索引到 SQLite 和检索的完整性、可追溯性、幂等性与安全边界。测试分层如下：

| 层级 | 范围 | 频率与门槛 |
|---|---|---|
| 单元 | 纯函数、状态机、ID、文本和切分规则 | 每次提交；全部通过 |
| 组件/契约 | 抽取→切分→索引→SQLite 的字段、状态、异常契约 | 每次提交；全部通过 |
| 真实集成 | 实际 PDF-001、PDF-002、PDF-008 端到端 | 每次管线变更；全部通过 |
| 全量验收 | 全 20 份、共 1,125 页及 Golden Set | 发布前；全部门槛通过 |
| 人工质量 | Golden Set 双人独立标注、分歧仲裁 | 发布前及检索策略变更后 |

不生成虚构 JSON；实际文件 hash、页数和元数据以现有 manifest 与运行结果为准。

## 单元测试（至少 8 项）

1. **hash**：相同字节得到稳定 hash，文件变化导致 hash 变化。
2. **页计数/边界**：空页、单页、末页、非连续外部页码均不越界，内部总页数准确。
3. **文本保留/规范化**：中英文、数字、单位、否定词、换行、连字符和表格文本按规则保留。
4. **replacement character**：检测 `U+FFFD`，按策略告警或失败；正常文本不误报。
5. **section 切分**：标题层级、跨页 section、页眉页脚和无标题页归属稳定。
6. **chunk 切分**：长度/重叠边界稳定，不跨文档或禁止跨越的 section，不写入空 chunk。
7. **稳定 ID/引用**：重复输入产生相同 document/section/chunk ID，并可反查页和 section。
8. **失败页/错误分类**：单页失败有完整记录，不伪装成成功；重试状态可查询。
9. **SQLite hash/事务**：hash 唯一、回滚后无孤儿数据，状态与数据一致。
10. **重复运行 skip**：同 hash、版本、配置时 skip；文件或版本变化时按策略重处理。
11. **检索排序/过滤**：文档和 section 过滤有效，稳定排序，返回引用实际存在。
12. **安全策略**：证据不足、权威性不足和高风险问题触发限定回答/拒答，不编造。

## 真实集成：PDF-001 / PDF-002 / PDF-008

对三份实际代表 PDF 从原始输入运行完整管线，并断言：输入 hash、实际页数、每页成功/合法空页/失败状态、section/chunk、ID 反向引用、replacement character、文本保留、SQLite 写入和检索证据均可核验。重复运行必须 skip 且不产生重复 chunk。另在文档边界和单文档处理中注入中断：已完成文档应 skip；中断文档按当前文档级事务模型整体重跑，最终结果必须与一次性运行一致。当前管道不承诺页级断点续跑。

## 全 20 份验收项

对 PDF-001 至 PDF-020 逐份记录实际值、pass/fail、证据路径与失败原因：

- **hash**：输入 hash 已计算，且与 SQLite/处理记录一致。
- **页数**：PDF 页数与处理页数一致；差异必须为 0 或有批准例外。
- **失败页**：失败页清单完整；目标为 0 个未解释失败页，例外必须可重试、可人工复核。
- **section/chunk**：均可用；无空 chunk、跨文档 chunk 或无法归属页的 chunk。
- **ID 引用**：document、section、chunk 全部可反查，无悬空、重复或错文档 ID。
- **replacement character**：`U+FFFD` 必须为 0；非 0 阻断发布。
- **文本保留**：固定抽样逐页对照原 PDF；标题、正文、数字、单位、否定词和关键表格不得有影响语义的丢失/篡改。
- **重复运行 skip**：输入、版本、配置不变时全 20 份进入 skip/等价幂等路径，数据库计数不增加。
- **SQLite hash**：每份可由 hash 唯一定位；hash、页数、状态、版本一致，无同 hash 冲突。
- **整体汇总**：20 份完成，页数合计必须为 1,125。

## 检索 Golden Set：建议 80 例

### 样本配额

- **60 个正例**：PDF-001 至 PDF-020 每份至少 3 个，覆盖不同页/section；建议中文 30、英文 30。
- **10 个负例/跨文档混淆**：无答案、相似术语/型号混淆、从错误文档推断；期望明确说明证据不足或找不到。
- **10 个权威性/安全拒答**：维修安全、法规/召回、扭矩/操作前提或权威证据不足的问题；不能把普通检索结果当作安全许可。

共 80 例；样本可有边界标签，但不得重复计数。每例锁定语言、主 `question_type`、期望文档、答案要点、正/负/拒答标签及证据要求。

### 英文和 `question_type` 配额

全部 80 例使用英文 query，不再维护中文 query 集。主类型配额：

- factual/specification：20
- procedure/maintenance：16
- diagnostic/troubleshooting：12
- comparison/constraint：10
- cross-document/confusion：8
- authority/safety refusal：10
- no-answer/negative：4

合计 80。最终表中每个样本只能有一个主类型；边界/安全标签另列，防止类别重叠造成统计歧义。

### 标注要求

两名标注员独立标注，再由第三人仲裁分歧。每个正例至少指定一个证据页和 section；多页结论列出所有必要页及各自支持要点。负例记录不能回答的理由及易误召回文档。安全/权威例标出风险前提、资料权威边界和必须限定/拒答的措辞；证据不足时 gold 不是猜测数值或步骤。

发布前目标：正/负/拒答标签一致率 ≥95%，证据页/section 一致率 ≥90%（可报告 Cohen’s kappa）；未达标先修订指南并重标。

## 检索质量与质量阈值

在固定索引、embedding/reranker 版本和 Golden Set 上报告总体及中英、各 `question_type`、各文档、正/负/拒答子集：

- **Hit@1 ≥ 0.85**：首个结果为 gold 文档且证据页/section 正确。
- **Hit@5 ≥ 0.95**：前五含可用 gold 证据。
- **MRR@10 ≥ 0.90**：按首个可用 gold 证据排名计算；无答案/拒答按预定义安全判定计分。
- **证据正确率 ≥ 0.90**；答案要点覆盖率 ≥90%。
- 关键数字、单位、否定条件不得错误；安全/权威例越权断言为 0，负例误答率 ≤5%。任何关键安全错误或某子集严重退化均阻断发布，不能被总体平均掩盖。

## 性能与失败恢复门槛

记录固定环境、并发、OCR、缓存、版本、资源峰值和完整日志；必须用全 20 份/1,125 页实测。完整处理率 100%，无未解释失败页、数据丢失或悬空引用；不得因持续内存增长 OOM。端到端总耗时及 P95 单页耗时不得超过已批准基线的 120%；若尚无基线，首次全量运行先建立基线，不虚构绝对秒数。

在文档完成后和文档处理中注入中断：重启后已完成文档不重复处理，中断文档整体重跑，最终 hash、页数、section/chunk 和引用与一次性运行一致。永久错误应记录到该文档失败结果并继续其他文档；重试不产生重复 chunk。异常退出后 SQLite 可打开，不能出现“成功无数据”或“有数据但状态失败”。全量再次运行必须按 hash/版本/配置 skip；仅变更受影响文档。页级断点续跑属于后续增强，不作为当前验收承诺。

## 发布条件

单元/组件、三份真实集成、20 份逐文档验收、Golden Set 指标、双人标注、性能、SQLite hash、重复运行 skip 和中断恢复全部通过，方可发布。replacement character 非零、页数不一致、hash 冲突、悬空 ID、未解释失败页和不可恢复部分写入均为阻断项。
